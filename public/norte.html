🟡 Parcial · existe pero fragmentado/incompleto8

User / Profile (Auth+sesión)🟡
`user_profiles`, `user_invitations`, `user_tenants`, `operario_pins`, `tms_drivers`
Concepto repartido (identidad/rol, PIN, conductor). Auth (token) lo maneja Supabase Auth, no tabla propia. Sin modelo unificado con `deviceId`/`vehicle`/`site`.
Invoice / Factura🟡
`invoices`
La **tabla** está 100% built (`0077`, F-YYYY-NNNN, total, status, paid). El `partial` es por el **gate legal (AUT-04)** — "exige aceptación legal vigente" — que NO está …
SyncBatch (outbox offline)🟡
`outbox_push_events`
`0066` es push de **salida** (server→device). NO existe cola offline-first de **entrada** del operario; el patrón se maneja client-side.
File / Archivo🟡
`warehouse_receipt_photos`, `bug_attachments`, `shipment_documents`, `back_assets`, `expenses`, `dispatch_pods`
No hay tabla genérica `File`; cada dominio referencia el binario por path/URL a Supabase Storage (`expenses.receipt_path`, etc.). Concepto cumplido pero fragmentado.
Route catalog / Rutas (config)🟡
`rates`, `dispatch_routes`, `dispatch_city_catalog`
La plantilla de costo multi-componente CN→VE (freight/customs/transport/handling/insurance/commission) **NO existe** como columnas: `rates` solo tiene per_cbm/flat/min.
City / Ciudad (config)🟡
`ve_locality_catalog`, `dispatch_city_catalog`
Destino VE bien modelado (estados/ciudades/CP). **Falta catálogo de origen CN** (ciudades/puertos de China). `ports` (`0096`) cubre puertos marítimos.
Rule / Regla (config)🟡
`dispatch_rules`, `mail_rules`
No hay catálogo genérico `rules`. Reglas especializadas por dominio (despacho, mailing).
Notification (WhatsApp/Email/Push)🟡
`mail_*` (logs/templates/rules/config/blacklist/signatures), `outbox_push_events`, `bug_notifications`, `user_notification_prefs`
Email con infra completa (`0018`). Push (`0066`). **WhatsApp NO tiene tabla de salida** persistida (es deep-link/handoff); Telegram tampoco. Sin tabla única multi-canal.
