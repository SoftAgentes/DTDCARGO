## Ejecución

El founder solicitó repetir el inventario read-only del Corte A. Se revalidaron
el repositorio, los contenedores y volúmenes Docker, la ausencia de
`supabase/config.toml` y el catálogo del único PostgreSQL activo mediante una
transacción `READ ONLY`.

No hubo migraciones, DDL, DML, seeds, inicio de servicios, lectura de payload,
acceso Cloud, push ni deploy.

## Resultado estable

- 18 migraciones contienen referencias a `entity_audit_log`;
- 23 sitios históricos de INSERT SQL convergen en cinco funciones writer;
- ocho archivos TypeScript insertan directamente y trabajan best-effort;
- `rendition` sigue ausente del CHECK final de 0241;
- los grants declarados siguen siendo SELECT para `authenticated` y ALL para
  `service_role`;
- el contenedor activo `ERP_HAMUDI` no tiene la tabla y no comparte el ledger;
- el contenedor detenido `hailuway-erp` pertenece a otro proyecto;
- DTD Cargo no tiene base Supabase local por contrato del repositorio.

La evidencia consolidada permanece en
[Inventario del Corte A](../specs/0166-auditoria-gobernada-aud-01-aud-02/inventario-corte-a-2026-07-21.md).

## Decisión de gate

No se intentará crear o iniciar una base local porque eso contradice el contrato
actual y excede el alcance read-only. Para completar la fotografía efectiva del
Corte A se requiere autorización concreta para consultar únicamente metadatos y
tipos distintos no sensibles del proyecto Cloud DTD.

La autorización de lectura no autorizaría reparar el catálogo ni aplicar una
migración.
