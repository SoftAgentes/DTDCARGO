## Decisión registrada

El founder autorizó completar en una tanda el diseño técnico pendiente de
SDD-0168 y publicar/integrar sus documentos. Se creó
[DT-SDD-0168 v1.0](../specs/0168-mp-01-comentarios-permanencia-restauracion/diseno-tecnico.md)
y [REV-MP-002](reviews/mp-01-comments-design.md) lo aprobó técnicamente para una
implementación local posterior por gates.

## Arquitectura fijada

| Área | Decisión |
|---|---|
| Despliegue | `DB-1 contrato aditivo → APP → DB-2 hardening` |
| Frontera | Server Action + RPC service-role-only |
| Estado | `deleted_at` existente + metadatos nullable, sin backfill |
| Atomicidad | comentario y AUD-01 en una transacción con row lock |
| Idempotencia | operation id y correlación durable |
| RBAC | `moderate_comments` y `restore_comments`, admin-only |
| Contextos v1 | `shipment` y `bitacora_task` |
| Ventanas | reloj DB: 10 s / 30 días / 90 días |
| Restauración | mismo registro y mismas relaciones |
| Direct update | retirado en DB-2; edición conserva grant por columna |
| Menciones | inbox y badge unidos al comentario activo |
| Undo | deadline del servidor independiente de pausa visual AVS |
| Purga | inexistente y fuera de alcance |

## Evidencia

- inventario de código, migraciones y pruebas actuales;
- metadata Cloud sin leer filas de negocio ni PII;
- A2 aplicada y catálogo AUD extensible;
- forma real de columnas, constraints, índices, triggers, functions, policies y
  ACL;
- tablas pequeñas y cero locks en espera durante el inventario;
- diseño de pruebas DB, aplicación, E2E, accesibilidad y forward-fix.

## Límites

Esta línea base no autoriza:

- escribir o aplicar DB-1/DB-2;
- modificar código, RBAC o UI;
- deploy de Preview/producción;
- nueva migración Cloud;
- hard-delete, Storage, jobs o purga;
- declarar completo el Corte D global de SDD-0166.

pruebas contractuales en worktree propio. Su commit, aplicación Cloud y los
gates APP/DB-2 se deciden por separado.
