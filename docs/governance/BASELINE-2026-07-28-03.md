## 1. Decisión

[REV-AUD-008](reviews/aud-corte-b1.md) aprueba técnicamente la implementación
local del Gate B1 de SDD-0166:

- migración `0267_audit_contract_append_only`;
- prueba contractual aislada con rollback;
- contrato audit v1 aditivo;
- writer `append_audit_event`;
- matriz append-only directa para roles de aplicación;
- único índice parcial por tenant/correlación;
- compatibilidad comprobada con siete writers SQL y el camino legacy.

La prueba quedó verde en PostgreSQL 15 y 17. No se aplicó ningún cambio en
Supabase Cloud.

## 3. Contrato local resultante

La migración añade:

- `correlation_id`;
- `source`;
- `result`;
- `reason`;
- `before_data`;
- `after_data`;
- `schema_version`;
- `sensitivity`.

Los eventos legacy reciben únicamente defaults honestos:
`source/result/sensitivity = legacy_unknown`, `schema_version = 1` y
campos sin evidencia en `NULL`.

El writer nuevo rechaza `legacy_unknown`, entidades inactivas, actores o
eventos inválidos, JSON no objeto, claves prohibidas, schema no positivo y
eventos gobernados sin motivo.

## 4. Matriz de acceso local aprobada

| Rol | Tabla | Writer |
|---|---|---|
| `PUBLIC` | ninguno | no |
| `anon` | ninguno | no |
| `authenticated` | `SELECT` | no |
| `service_role` | `INSERT` | sí |
| `postgres`/owner | administrativo | sí |

La policy `entity_audit_log_service_role_all` se retira. RLS,
`entity_audit_log_tenant_select` y Realtime permanecen.

## 5. Compatibilidad preservada

B1 no migra callers:

- siete funciones SQL continúan operativas;
- ocho writers TypeScript conservan INSERT directo temporal;
- el viewer conserva `SELECT authenticated`;
- la publicación Realtime no cambia;
- las nueve columnas históricas no cambian.

La migración de consulta pertenece a Corte C. La migración de writers y la
atomicidad por dominio pertenecen a Corte D.

## 6. Excepción de ciclo de vida

`entity_audit_log_tenant_id_fkey` conserva `ON DELETE CASCADE`. Por ello, B1
demuestra inmutabilidad directa frente a roles de aplicación, no append-only
absoluto ante el borrado del tenant.

Antes del cierre global de SDD-0166 se requiere un diseño separado de ciclo de
vida del tenant/fixtures. Esta línea base no autoriza una función de purga,
retención, borrado de datos ni cambios en `scripts/cleanup-e2e.ts`.

## 8. Límite de autorización

Esta línea base:

- registra implementación, prueba y revisión técnica local;
- permite un commit local selectivo dentro de la allowlist B1;
- no autoriza push, integración o aplicación Cloud;
- no abre Cortes C–E;
- no migra callers, viewer ni RBAC;
- no modifica Supabase Cloud, Vercel o datos;
- no reabre SDD-0168.

## 9. Próximo gate

aplicar solo `0267_audit_contract_append_only` en Cloud mediante el runbook,
con preflight fresco, postcondiciones, prueba transaccional y advisors.
